# /tdd — 테스트 먼저, 그다음 고친다

요청: $ARGUMENTS

테스트는 의존성 없이 `node --test tests/*.test.mjs`로 돈다. 파일을 고칠 때마다 PostToolUse 훅(`.claude/hooks/run-tests.mjs`)이 전체 테스트를 돌리고, 실패하면 결과를 돌려준다. 훅 결과를 매 단계의 확인으로 쓴다.

## 0. 무엇을 확인할지 정한다
- 요청을 "입력 → 기대 결과" 한두 문장으로 적는다. 기대 결과는 `CLAUDE.md`, `.claude/rules/*`, `work/seoul-parking/`(PRD·`copy.json`·`tokens.json`)에서 근거를 찾는다. 근거가 없거나 산출물과 요청이 어긋나면 테스트를 쓰기 전에 묻는다.
- 범위 밖(PRD "범위 밖") 기능이면 멈추고 묻는다.
- 빈자리·요금·시각 같은 숫자는 `data/parkings.json` 실제 값이나 규칙에서 나온 값만 쓴다. 지어내지 않는다.

## 1. 빨강 — 실패하는 테스트를 먼저 쓴다
- 기존 파일에 맞는 자리에 넣는다.
  - `tests/app.test.mjs` — `index.html` 스크립트의 도우미(`isStale`, `band`, `columnPx`, `hours`, `addr`, `oldest`, `esc`, `kst` 등)와 화면 문구·출처. 새 도우미를 시험하려면 `load()`의 `globalThis.__ = {...}` 목록에 이름을 더한다. 도우미는 `// ---- 지오메트리 ----` 줄 위에 있어야 DOM 없이 실행된다.
  - `tests/data.test.mjs` — `data/parkings.json` 스냅샷 형태·필드 대응·두 사본 일치·인증키 노출.
- 테스트 하나는 동작 하나. 이름은 한국어로 "무엇이 어떠하다" 꼴(기존 테스트와 같게).
- 테스트를 쓴 직후 훅이 돌린 결과에서 **새 테스트가, 기대한 이유로** 실패하는지 본다. 
  - 바로 통과하면 이미 되는 동작이거나 테스트가 헐겁다. 테스트를 고치거나 사용자에게 알린다.
  - 문법 오류·`undefined` 접근처럼 엉뚱한 이유로 실패하면 테스트부터 바로잡는다.
- 이 단계에서는 제품 코드(`index.html`, `data/`)를 건드리지 않는다.

## 2. 초록 — 통과할 만큼만 고친다
- 테스트를 통과시키는 가장 작은 수정을 `index.html`(또는 해당 파일)에 한다. `.claude/rules/index-html.md`의 토큰·문구·`esc()`·reduced-motion 규칙을 지킨다.
- 훅 결과에서 새 테스트와 **기존 테스트 전부**가 통과하는지 본다. 기존 테스트가 깨지면 테스트를 고치지 말고 코드를 고친다(테스트가 틀렸다고 판단되면 근거와 함께 사용자에게 묻는다).
- 테스트를 통과시키려고 테스트를 약하게 만들거나 `skip`·`todo`로 돌리지 않는다.

## 3. 정리 — 초록을 유지한 채 다듬는다
- 중복 제거, 이름 정리, 상수는 `T` 한 곳에서. 동작은 바꾸지 않는다.
- 고칠 때마다 훅이 초록인지 확인한다.

## 4. 마무리
- `node --test tests/*.test.mjs`를 한 번 직접 돌려 최종 결과를 확인한다.
- 화면에 보이는 변화가 있으면 `python3 -m http.server`로 열어 390×844에서 확인할 수 있다고 안내한다(테스트로는 레이아웃을 보지 않는다).
- 사용자에게 알린다: 추가한 테스트(이름), 처음 실패한 이유, 고친 내용, 최종 통과 수. 커밋은 요청이 있을 때만 하고, 커밋하면 테스트와 수정을 한 커밋에 담는다.
