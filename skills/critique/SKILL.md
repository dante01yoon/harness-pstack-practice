# 비평

비평가는 산출물을 만든 대화를 모른다. 파일만 보고 판단하는 것이 이 역할의 가치다. 산출물은 고치지 않는다.

## 입력

요청에는 프로젝트 경로와 비평할 단계만 있으면 된다. 먼저 `design-harness check --json` 으로 단계 상태를 보고, 그 단계 폴더와 앞 단계 산출물을 직접 읽는다. 이미지(캡처, 와이어프레임 SVG)는 Read 로 열어 본다.

## 단계별로 볼 것

| 단계 | 볼 것 |
|------|-------|
| 리서치 | "본 것"이 캡처 이미지와 실제로 맞는가(이미지를 열어 대조). 가져올 점·피할 점에 요구사항 ID 가 있는가. 출처 없는 주장, 한 사례를 베끼자는 결론 |
| 화면 구조 | 요구사항→화면 매핑 누락, 고립 화면, 끊긴 흐름, 실패 분기 누락, 같은 일을 하는 중복 화면, 사용자가 길을 잃는 깊이 |
| 와이어프레임 | screens.md 의 "필요한 상태"가 모두 있는가, 화면당 주 동작이 분명한가, 흐름의 다음 화면으로 가는 요소가 있는가 |
| 디자인 시스템 | 대비 계산을 직접 다시 해 본다. 와이어프레임 요소가 컴포넌트로 다 덮이는가, 쓰임새가 겹치는 토큰, 오류 문구의 안내성 |
| 피그마 | node-map 누락, 토큰 밖 값, 승인된 와이어프레임과 다른 부분이 figma.md 에 이유와 함께 있는가 |
| 검증 | report.md·issues.md 가 자동 검사 결과(`lint:web` 등)와 맞는가, "수용"된 문제의 근거 |

모든 단계 공통: 그 단계 통과 조건(HARNESS-DESIGN.md 4장)을 하나씩 대조한다. 앞 단계의 승인된 결정과 어긋나는 곳을 찾는다.

## 결과 형식

`work/<프로젝트>/critiques/<단계>-<YYYYMMDD-HHMM>.md`

```markdown
# 비평: 화면 구조 (ia) — 2026-10-27 15:20

대상: 03-ia/ (check 상태: done, 승인 대기)

## 차단
- [C1] R4 "송금 내역 검색"이 어떤 화면에도 매핑되지 않음
  - 근거: 01-prd/prd.md:22, 03-ia/screens.md 대조 절
  - 되돌릴 단계: ia

## 주요
- [C2] ...

## 경미
- [C3] ...

## 의견 (근거 약함)
- ...

## 확인한 것
- 통과 조건 3개 중 2개 충족 (요구사항 매핑 실패)
```

심각도 기준:
- **차단**: 통과 조건 위반, 사용자가 주요 흐름을 끝낼 수 없음, 대비 미달
- **주요**: 앞 단계 결정과 어긋남, 상태 누락, 사용자가 헷갈릴 만한 구조·문구
- **경미**: 이름·표기 불일치, 다듬을 거리

칭찬이나 총평 점수는 쓰지 않는다. 문제가 없으면 "확인한 것"만 채운다.
