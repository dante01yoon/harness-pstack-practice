# 화면 구조 (03-ia)

입력: `01-prd/prd.md`, `02-research/insights.md`
출력: `03-ia/sitemap.md`, `03-ia/screens.md`, `03-ia/flows.md`
통과 조건: 모든 요구사항 ID 가 화면 하나 이상에 매핑, 고립 화면 없음, 주요 흐름이 끝까지 이어짐. **사람 승인 필요.**

## 화면ID 규칙

`S01`, `S02` … 처럼 짧게 짓는다. 이 ID 가 와이어프레임 파일명(`04-wireframe/S01.md`), Figma node-map, 핸드오프 스펙 파일명으로 끝까지 쓰인다. 한번 승인되면 바꾸지 않는다.

## screens.md 형식

```markdown
# 화면 목록

| ID | 이름 | 목적 | 진입 경로 | 요구사항 | 필요한 상태 |
|----|------|------|-----------|----------|-------------|
| S01 | 로그인 | 계정 확인 | 앱 시작(비로그인) | R1 | 오류, 로딩 |
| S02 | 홈 | 잔액 확인, 송금 시작 | S01 성공, 탭바 | R2, R3 | 빈 상태, 로딩 |
```

"필요한 상태"는 다음 단계 와이어프레임의 `## 상태: <이름>` 절이 된다. 목록·검색·입력·네트워크가 있는 화면은 빈 상태·오류·로딩을 따져 본다.

## sitemap.md

화면 계층을 들여쓰기 목록으로. 탭바·모달·외부 링크처럼 진입 방식이 다른 것은 표시한다.

## flows.md

주요 사용자 흐름마다 시작 조건 → 화면 순서 → 끝 상태. 실패 분기(오류, 취소)도 적는다.

```markdown
## F1 송금
시작: 홈(S02)에서 "송금"
S02 → S05 받는 사람 → S06 금액 → S07 확인 → S08 완료
- 잔액 부족: S06 에서 오류 상태, 진행 막음
- 취소: 어느 단계든 S02 로
끝: S08 에서 홈으로, 잔액 갱신
```

## 끝내기 전 대조 (screens.md 맨 아래에 남긴다)

```markdown
## 대조
- 요구사항 → 화면: R1 S01 / R2 S02 / … / 매핑 안 됨: 없음
- 진입 경로 없는 화면: 없음
- 흐름 끊김: 없음
- PRD 에 없음 — 확인 필요: 비밀번호 재설정 화면
```

빈칸이 있으면 직접 채우거나, 결정이 필요한 것은 사람에게 물을 목록으로 돌려준다. 이 단계는 승인이 필요하므로 끝나면 멈춘다. `design-harness approve` 는 실행하지 않는다.
