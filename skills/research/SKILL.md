# 리서치 (02-research)

입력: `01-prd/prd.md`(요구사항 ID), `01-prd/open-questions.md`
출력: `02-research/research.md`, `02-research/references/`(links.md, *.png, captures.json), `02-research/insights.md`
통과 조건: 사례 최소 3개 분석, 모든 인사이트가 요구사항 ID 와 연결, 출처 없는 주장 없음. 사람 승인은 필요 없지만 끝나면 요약을 보고한다.

## 순서

1. **PRD 읽기.** 요구사항 ID 목록과 대상 사용자를 뽑아 둔다. 리서치 질문은 요구사항에서 나온다("R3 결제 흐름을 다른 서비스는 몇 단계로 끝내나").
2. **사례 고르기.** 경쟁·인접 서비스 3~6개. 고른 이유를 한 줄씩 남긴다. 웹 검색은 이 단계에서만 쓴다.
3. **링크 적기.** `references/links.md` 에 사례별 URL 을 적는다. 사례 하나에 화면 여러 개를 봐도 된다.
   ```markdown
   ## 토스 송금
   - https://toss.im/...   ← 메인
   ```
4. **캡처.** `design-harness refs:capture` (모바일 기준이면 `--viewport mobile` 로 한 번 더). 실패한 URL 은 이유를 기록하고, 대체 화면을 찾거나 "확인 못 함"으로 둔다.
5. **이미지 보기.** `references/*.png` 를 **하나씩 Read 로 연다.** 이미지를 열기 전에는 그 화면에 대해 쓰지 않는다. 화면에 실제로 보이는 것만 적는다: 배치, 정보 위계, 주요 버튼 문구, 입력 단계 수, 빈 상태·오류 표시 방식, 색·글자 크기 인상.
6. **research.md 쓰기.** 사례마다 아래 형식.
7. **insights.md 쓰기.** 사례를 가로질러 요구사항별로 묶는다.
8. **확인.** `design-harness check` 로 리서치 단계에 빠진 것이 없는지 본다.

## research.md 형식

```markdown
# 리서치

## 사례 1: <서비스명> — <화면 이름>
- 출처: <URL> (캡처 `references/<파일>.png`, <capturedAt>)
- 고른 이유: <한 줄>

### 본 것
- 상단에 잔액, 그 아래 큰 "송금" 버튼 하나. 보조 동작은 아이콘 4개로 접혀 있음
- 금액 입력은 숫자 키패드 전체 화면, 확인까지 3단계

### 가져올 점
- [R2] 주 동작을 화면당 하나로 두는 위계 — 첫 화면에서 할 일이 바로 보임

### 피할 점
- [R5] 수수료 안내가 회색 12px 로 하단에 있어 놓치기 쉬움 — 우리는 금액 옆에 둔다

### 확인 못 함
- 로그인 뒤 화면 (로그인 벽)
```

- "본 것"에는 판단을 섞지 않는다. 판단은 "가져올 점 / 피할 점"에 쓴다.
- 가져올 점·피할 점은 각각 `[요구사항ID]` 로 시작한다. 연결할 ID 가 없으면 그 항목은 빼거나 "PRD 밖 관찰"로 따로 둔다.
- 캡처에 없는 정보(다른 기사, 앱 리뷰 등)를 쓰면 그 출처 URL 을 같은 줄에 단다.

## insights.md 형식

```markdown
# 인사이트

## R2 첫 화면에서 할 일을 바로 찾는다
- 가져올 것: 주 동작 하나를 크게 (사례 1, 3)
- 피할 것: 동작 6개 이상을 같은 무게로 나열 (사례 2)
- 화면 구조에 넘길 질문: 보조 동작을 탭바로 둘지 더보기로 접을지
```

## 하지 않는 것

- 캡처를 보지 않고 서비스 이름만으로 아는 내용을 쓰기
- 사례 화면을 그대로 베끼자는 결론. 가져올 점은 "원리"로 적는다
- `03-ia/` 등 다른 단계 폴더에 쓰기, `design-harness approve`·`review` 실행
