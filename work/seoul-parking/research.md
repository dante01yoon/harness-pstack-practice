# research: seoul-parking

## 핵심 과업
출발 전 휴대폰 웹에서 목적지 근처 서울시 공영주차장의 빈자리 수와 그 기준 시각을 3D 지도 위 기둥으로 바로 읽는다.

## 관찰한 패턴
- 지도 위 상태 표현: 서울시 주차정보안내시스템(r1)은 핀 색(만차/혼잡/원활/기본정보)과 하단 범례를 쓰지만 핀에 빈자리 숫자가 없고 핀끼리 겹친다. 우리는 기둥 높이 + 위 라벨로 숫자를 직접 보인다. 실시간 없는 주차장은 r1처럼 별도 상태(회색)로 구분한다.
- 높이+색 데이터 기둥: deck.gl(r8)은 높이와 색 이중 부호화로 많고 적음을 한눈에 보여 주지만 기둥이 빽빽하면 개별 값이 안 읽힌다. 우리는 122곳이라 라벨이 가능하다.
- 3D 건물과의 구분: MapLibre 예시(r3, r4)는 건물도 입체이며 OpenFreeMap 스타일에서 fill-extrusion을 쓴다. 건물은 연한 무채색, 기둥은 채도 있는 색으로 분리한다. 저작권은 지도 하단 작은 칩(r3, r4, r8)으로 둔다.
- 모바일 지도 첫 화면: 카카오맵(r2)은 지도 전체 화면 위에 검색창과 컨트롤(현위치, 확대/축소)을 띄우지만 앱 설치 모달이 첫 화면을 덮는다. SpotAngels(r5)는 검색과 앱 유도뿐이라 빈자리를 바로 못 읽는다. 두 가지 모두 피한다.
- 큰 알약형 전환 버튼(r5의 시간제/월정액)은 지도/목록 전환의 참고.

## 수집 한계
- 8개 중 7개 사용, 1개 차단(r6 따릉이, 웹 방화벽 화면, 우회하지 않음).
- 첫 시도의 MapLibre URL 두 개는 404여서 올바른 주소로 교체했다.
- 바텀시트와 목록 전환, 데이터 신선도("오래됨") 표기는 계정 없이 볼 수 있는 모바일 웹 화면에서 직접 확인하지 못했다. r2의 시트·r1의 정보 화면은 지도 화면 위주로만 캡처됐다. 해당 부분은 사람에게 직접 찍은 화면(네이버/카카오맵 앱의 주차장 시트, 따릉이 앱의 기준 시각 등)을 요청할 수 있다. 확인 못한 것을 본 것처럼 쓰지 않았다.
- 캡처는 첫 화면 한 장이고 인터랙션(탭, 스크롤)은 보지 않았다.

## 데이터에서 본 것(PRD의 2026-10-27 실제 API 응답 기준, 새로 만든 수치 없음)
- 실시간 122곳 중 연계 109곳, 없음 13곳. 좌표 연결 117곳, 위치 정보 없음 5곳.
- 122곳이면 기둥이 deck.gl 예시처럼 빽빽하지는 않지만 도심에서는 겹칠 수 있다. 줌 단계별 라벨 표시 규칙이 필요하다.
- 연계 없는 13곳은 r1의 기본정보 핀처럼 숫자 없이 구분되어야 한다.
